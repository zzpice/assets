# 图片资源库维护说明

## 按任务查规则

先按任务阅读对应规则，再按本页的[更新与检查](#更新与检查)生成并验证；以下路径和命令均以仓库根目录为准。

| 维护任务 | 规则与来源 | 人工维护位置 |
| --- | --- | --- |
| 壁纸、普通头像 | [归档与命名](../README.md#归档)、[来源记录](../wallpapers/SOURCES.md)、[壁纸设备](#壁纸设备) | 原图；`catalog.json` 对应图片的 `title`、`note`、壁纸 `device`；来源记录 |
| 图标 | [分类、标准与维护](../icons/README.md)、[逐项来源与许可](../icons/SOURCES.md) | 原图；图片 `title`、`note`、`source`、`license`；来源清单与许可文件 |
| 银行卡面 | [原版、修改版与来源](../bank-cards/README.md) | 原图；`catalog.json` 的 `cardBanks`、图片 `source` 或 `derivedFrom` 与修改说明 |
| 游戏封面、作品简介 | [收录、选图与作品资料](../game-covers/README.md) | 原图；`catalog.json` 的 `gameSeries`、`games`、图片 `path`／`source`／可选 `cover` |
| 女优人物、头像、年度榜与名人堂 | [人物与榜单规则](../actresses/README.md)、[名人堂标准](../actresses/HALL-OF-FAME.md#判断标准) | `actresses/data.json`、审核后的 `actresses/rankings/<年>.json`、每人的唯一源图 |
| 其他图片 | [通用归档](../README.md#归档)、[上传约定](#上传约定) | 原图；`catalog.json` 对应图片的 `title` 与必要的 `note` |
| 网站界面、分类名称与离线行为 | [界面与离线缓存](#界面与离线缓存) | `index.html`、`app/site.js`、`app/site.css`、`app/actresses.js`、`app/catalog.js`、`app/theme.css` 等界面文件及 `sw.js` 的行为逻辑 |

`catalog.json` 同时保存人工资料和生成内容。分类、尺寸、大小、内容标识、预览地址由工具读取原图与目录生成，不手改这些字段；人物的 `catalog.actresses` 和对应图片记录从人物登记及年度快照生成。卡面、游戏和人物须在运行生成器前完成所需登记与来源审核。

分类说明保存现行规则，来源清单和许可文件保存逐项依据；带日期的审核记录保留当时的审查范围与结果，不作为实时收录清单。提交与分支约定见 [AGENTS.md](../AGENTS.md)。

## 网页维护普通图片

打开图库顶部「上传图片」，或在图片全屏预览中点「编辑图片」。支持壁纸、普通头像、常规图标；游戏、银行卡面和人物资料继续按任务索引维护。技术尺寸与格式自动读取，分类、名称、来源和许可由维护者确认；新增与替换必须填写来源、许可（未确认可明确填写待核实），不自动修图。

改名、移动、替换、删除前显示图片、路径、资料变化与外链风险。仅在检查并保存时使用限权 PAT：只授权 zzpice/assets，Contents 读写；仓库权限、图片及资料基线、目标冲突和 main 版本均检查。Token 在输入后立即清空，只在本次检查与提交的内存中保留，返回修改、关闭、失败或保存后清除，不写入存储、配置、来源或日志。多文件通过 Git Data API 创建一个提交，最后非强制更新 main；并发更新或分支规则拒绝则停止，不创建 PR、不绕过保护。GitHub 原始错误响应不回显。

图片与 catalog 人工资料、来源记录在一次提交内保存。改名自动更新已有来源链接及导航图标来源登记的路径，历史来源记录保留。网页成功仅表示已提交；通过结果中的 Actions 链接确认部署，部署后关闭所有图库页面并重开以使用完整新版本。Token 无需 Pull requests 或 Workflows 权限。

## 上传约定

- 先阅读根目录 README 和现有目录，按上表确认资源用途与专属规则；内容分类优先复用已有目录，有实际需要时再新增。
- 壁纸的内容分类与适用设备分开处理；普通头像不按横竖方向分类，也不只凭方形尺寸认定为头像。
- 默认保留原图尺寸、格式和画面，不擅自裁剪、放大或重新压缩。目录尺寸以工具读取的实际显示尺寸为准；放大处理需在 `note` 中注明来源尺寸和处理方式，专属资源另按其图片规则处理。
- 文件名描述主体或场景，使用小写英文、数字和短横线。上传前检查重复图片及同名文件，只有明确替换时才覆盖；银行卡原版不得覆盖。
- 新图生成目录后补充易辨识的 `title`：壁纸与普通头像使用中文描述，图标遵循所属目录的品牌命名约定。游戏和人物标题由各自登记资料生成。壁纸检查 `device`，无法判断时保留 `unknown`。
- 壁纸与普通头像的出处、生成说明及许可依据记录在 [wallpapers/SOURCES.md](../wallpapers/SOURCES.md)；自制或生成不等于自动采用开放许可，不能从下载站名称推定作者或授权。

## 更新与检查

使用 Python 3.10 或更新版本，安装一次依赖；运行 JavaScript 测试还需 Node.js：

```sh
python3 -m pip install -r scripts/requirements.txt
```

添加、替换或删除图片，或修改展示资料后运行：

```sh
python3 scripts/update_catalog.py
```

本地维护可把原图、人工登记与工具生成的变化一起提交，包括 `catalog.json`、`app/previews/`、`index.html` 和 `sw.js`。工具读取实际尺寸、分类、大小和内容标识，生成小型预览及最长 1920×1200 的壁纸背景 WebP，输出 `wallpapers/index.json`，清理失效预览，保留原图。Actions 每次构建自动运行同一生成器，并直接部署生成后的白名单产物；不把生成结果自动提交回仓库，不会循环触发。网页维护不需要手动运行脚本。壁纸和普通头像目录尺寸写错时会停止并指出正确尺寸。

新增普通图片可先生成条目，再补标题和必要说明；卡面、游戏封面和人物先按专属规则登记。手动修改资料后再次运行更新命令，让缓存版本同步。修改界面文件后的步骤见[界面与离线缓存](#界面与离线缓存)。

提交前运行：

```sh
python3 scripts/update_catalog.py --check
```

此命令只检查、不写文件；它检查路径、尺寸、图标标准、各类登记约束及生成文件是否同步。内容分类、适用设备、人物身份、来源可信度和选图质量仍须按专属规则人工判断。

修改生成器、界面脚本、样式或离线逻辑时，还须运行与 [图库检查与部署](../.github/workflows/check.yml) 一致的现有验证：

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
node --check app/catalog.js
node --check app/site.js
node --check app/actresses.js
node --check sw.js
node --test scripts/test_*.cjs
```

仅修改 Markdown 文档时，检查相对链接并运行上述 `--check` 即可，无需重新生成目录和预览。人物来源审核的命令与只读 Actions 报告见[更新与审核](../actresses/README.md#更新与审核)，报告不自动更新发布内容。

## 标题与处理说明

展示标题和处理说明可在 `catalog.json` 对应图片的 `title` 和 `note` 中编辑，两者必须为字符串，图片路径不能重复。普通资源替换原图后保留标题、说明、来源、许可及其他有效人工资料；本地同用途改名或移动会按唯一匹配的原图内容保留资料，匹配不唯一时停止，须先明确更新 catalog 中的 path；替换前请在网页核对并修正不再适用的说明；游戏和人物的编辑位置及生成字段见上表。GIF 的列表预览显示首帧，下载保留动画；SVG 使用原矢量图预览。

## 壁纸设备

适用设备会按实际尺寸和比例初步分类为手机、电脑、平板；无法明确区分的尺寸（例如 1080×1920）保留为「待分类」。可在 `catalog.json` 中用 `device` 修正：`phone`、`desktop`、`tablet`、`unknown`，手动分类优先。只有手机竖屏壁纸提供锁屏效果，其他图片使用普通预览。

设备表示经确认的使用场景，不等同于画面方向；例如现有 7500×5000 的 3:2 壁纸仍属于电脑壁纸。继续使用 `wallpapers/<内容分类>/<尺寸>/` 归档，不为设备再复制或移动原图。网页的设备入口独立于折叠筛选，方向和尺寸选项随上级条件更新；只有实际存在多个取值时才显示对应筛选，已选条件仍可清除。新增资源时无需手工维护菜单，仍须核对内容分类与 `device`。

## 界面与离线缓存

修改界面脚本、样式或离线逻辑后也运行 `python3 scripts/update_catalog.py`，并提交 `index.html` 和 `sw.js` 的变化，按[更新与检查](#更新与检查)完成验证。工具会生成界面、目录及必需资源的内容校验值，完整校验和缓存成功后才安装新版本；后台更新在关闭所有图库页面、重新打开后使用。打开期间继续使用同一版本的界面与目录，不读取实时 GitHub 文件树。

离线缩略图最多保留 32 张，图标预览最多保留 64 个；图标按原文件的内容标识缓存，替换图标后不会复用旧版本。更新界面时保留仍在目录内的预览缓存；新版本优先预缓存壁纸和头像，明确排除人物图库的头像，下载原图仍需联网。人物图库可通过页脚默认折叠的「更多」或原有直达网址进入，可在自己的浏览器内选择保留导航入口；这不改变公开目录和资源的访问边界，详见其目录内的访问说明。

安装时可选预览的网络预取最多等待 8 秒，超时会取消未完成的预取，让已完整校验的界面完成安装；必需界面文件仍须全部校验成功。游戏封面的模糊背景随对应懒加载图片成功加载后显示，避免背景提前请求远处的封面。

## 网页结构与发布

`app/catalog.js` 是无 DOM 的分类、查询、尺寸与排序模块，浏览器和 Node 检查使用同一实现；`app/site.js` 负责状态、路由、列表与对话框，`app/actresses.js` 负责独立人物资料。`app/theme.css` 维护本项目的基础变量，`app/theme.js` 管理外观选择，`app/site.css` 维护布局。桌面侧栏和移动端横向用途导航共用 DOM；内容区按搜索、筛选、结果和图片排列。

主题偏好只保存于 `zzpice-assets-theme`；恢复系统时移除此键，系统变化和同站其他标签页会实时同步。内联初始化在外部脚本与样式下载前设置背景、原生控件外观和 `theme-color`，存储不可用时仍可在当前页面切换。全屏看图维持独立深色底和完整深色控件，图标预览保留浅色衬底以检查透明区域。浅深两份 manifest 共用固定安装 ID `/assets/`、相对 `scope / start_url` 和 `icons`，当前外观决定安装描述；操作系统启动画面可能缓存安装时描述，不保证已安装应用立刻更新。新增主题脚本和 manifest 均由生成器纳入完整离线外壳。原相对 ID 实际解析为同域根路径，与基金工具冲突；已安装旧版者可移除旧图标再安装，网址、收藏和主题存储位置不变。

生成器的 `VERSIONED_ASSETS` 是必需界面文件的单一声明，驱动版本链接、内容校验和 Service Worker 安装清单。新增必需文件时改这里，再运行生成与检查，不在多个列表中各补一份。

真实浏览器检查：

```sh
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install --with-deps chromium webkit
node scripts/browser-check.cjs
```

功能检查使用独立受控目录与图片，覆盖两引擎、桌面 / 手机 / 平板、收藏、筛选、分享网址、预览关闭后的焦点和错误重试；发布目录另检查真实图标和缓存；Chromium 还执行离线重载。Playwright WebKit 离线导航存在驱动限制，Safari 的冷启动需真机确认。

CI 的纯图片或 catalog 资料修改仅执行资源规范校验、目录生成与发布组装；界面、生成器、缓存行为和工作流修改才执行现有单元与浏览器检查。缓存版本和校验清单的生成变化本身不会触发浏览器回归。CI 先组装 `build/pages`，再按需用 `SITE_ROOT=build/pages` 运行浏览器检查；测试直接服务发布目录。Pages 由 Check gallery 在所有检查通过后发布，白名单包含网页、目录、应用资源与原始图片目录。维护脚本、测试、来源审核临时报告与开发依赖不进入站点产物；原始图片的公开地址不变。修复或撤销问题提交后重新运行工作流即可恢复。
