# 图片目录维护

## 上传约定

- 先阅读根目录 README 和现有目录，确认用途为壁纸、头像、图标、银行卡面、游戏封面或其他资源；内容分类优先复用已有目录，有实际需要时再新增。
- 壁纸的内容分类与适用设备分开处理；头像不按横竖方向分类，也不只凭方形尺寸认定为头像。
- 默认保留原图尺寸、格式和画面，不擅自裁剪、放大或重新压缩。目录尺寸以工具读取的实际显示尺寸为准；放大处理需在 `note` 中注明来源尺寸和处理方式。
- 文件名描述主体或场景，使用小写英文、数字和短横线。上传前检查重复图片及同名文件，只有明确替换时才覆盖。
- 新图生成目录后补充易辨识的 `title`：壁纸与头像使用中文描述，图标遵循所属目录的品牌命名约定。壁纸检查 `device`，无法判断时保留 `unknown`。新增第三方图标还须更新 `icons/SOURCES.md`、分类数量和相应许可文件。
- 壁纸与头像的出处、生成说明及许可依据记录在 `wallpapers/SOURCES.md`；自制或生成不等于自动采用开放许可，不能从下载站名称推定作者或授权。
- 图标按[用途分类](../icons/README.md)归档。新分类会自动追加到已有分类之后；需要调整默认顺序或中文名称时更新 `app/site.js` 的分类清单和图标说明。
- 银行卡面先按[卡面规则](../bank-cards/README.md)登记银行及来源，再运行工具。原版必须提供来源集合 `collection`、允许的钱包 `wallet`、原文件 HTTPS 地址 `url`、匹配的 `sha256`、正整数 `cardId` 和 `assetId`、`YYYY-MM-DD` 获取日期 `retrieved`；修改版必须用 `derivedFrom` 关联原版。地区和银行顺序由 `catalog.json` 的 `cardBanks` 清单维护。

- 游戏封面按[收录规则](../game-covers/README.md)确认正式封面身份和来源，默认一作一图，保留源文件尺寸与比例。在 `catalog.json` 登记系列、作品名称与首发年，每张图片只需填写 `path` 和 `source`；平台、地区与简短版本说明可选。标题、作品归属、实际尺寸和预览由工具生成，没有首版或高清准入门槛。代表封面在真实性、构图完整度和实际画质相近时优先正式英文版；不能为了语言统一牺牲画质或构图，`extras` 不强制统一语言。

作品的可选 `synopsis` 同时记录无剧透简介 `text` 和介绍依据 `source`，优先官方资料；同一作品只维护一次。生成器保留并校验简介及 HTTP(S) 依据链接，网页在现有封面卡片内折叠展示。

## 更新与检查

女优人物图库遵循[人物与榜单规则](../actresses/README.md)：唯一登记表为 `actresses/data.json`，每人一张源图，年度使用带来源的 `rankings/<年>.json`。不要直接改生成的 `catalog.actresses`、按名称建重复人物或按年份复制头像。`actress_sources.py` 只在仓库外生成审核报告，不自动更新发布内容。人物登记、来源快照、原图和生成文件一起提交；`app/actresses.js` 与既有界面同样由更新命令生成页面和离线缓存版本。

人物展示名变更须保留原主名及其来源到 `aliases`，不要修改身份映射或排名来源表记。`japaneseName` 和 `romanization` 只能选已带来源的姓名／别名，展示名独立。基本资料的可选 `profile` 只保存经人工核对的生日／出生年、身高和明确定义的 AV 出道年份，保留原文来源姓名、URL、获取日期、页面 SHA-256 与审核日；不同字段的独立出处使用可选 `fieldSources.<字段>` 证据数组，每条包含 `sourceName`、`source` 和 `reviewed`；未指定的字段沿用默认来源。证据必须对应已记录的字段及同一已确认人物，不允许空数组、重复 URL 或缺失摘要／审核。出生年份不能自动补成日期，资料缺失不填默认值。不维护当前事务所／厂牌、活动状态、社交账号、三围或罩杯；来源元数据可以注明原网站名称。源页面动态更新不等于人物字段改变，不从广告、作品列表或头像分组推断人物属性，聚合库只供发现候选和核验，不静默覆盖可靠原始资料。

女优头像的可选 `portrait.display` 仅指列表／详情预览的人工取景，`crop` 为 EXIF 校正后源像素 `[x,y,width,height]`，`sourceSha256` 必须对应当前原图，并附审核日。先比较其他原图候选，确需取景时检查完整头部、姿态与肩部；不要批量套用中心裁切。生成器只缩小派生预览，不拉伸、不放大、不改变下载源文件。调整裁切会更换预览内容地址并清理旧文件；换图必须重新审核裁切或删除旧取景，源 SHA 不符、越界或无审核记录会停止生成。

使用 Python 3.10 或更新版本，安装一次依赖：

```sh
python3 -m pip install -r scripts/requirements.txt
```

添加、替换或删除图片后运行：

```sh
python3 scripts/update_catalog.py
```

把原图和工具生成的变化一起提交，包括 `catalog.json`、`app/previews/`、`index.html` 和 `sw.js`。工具读取实际尺寸、从目录读取风格分类、更新文件大小和内容标识、生成小型 WebP 预览、移除不再使用的预览，始终保留原图。壁纸和头像目录尺寸写错时会停止并指出正确尺寸。

`icons/` 下的图标须为 512×512 PNG、RGBA，r=115 圆角外侧完全透明。工具会检查并拒绝不合规文件，不自动修图，也不生成重复预览。

修改界面脚本、样式或离线逻辑后也运行同一命令，并提交 `index.html` 和 `sw.js` 的变化。工具会生成界面、目录及必需资源的内容校验值，完整校验和缓存成功后才安装新版本；后台更新在关闭所有图库页面、重新打开后使用。打开期间继续使用同一版本的界面与目录，不读取实时 GitHub 文件树。

离线缩略图最多保留 32 张，图标预览最多保留 64 个；图标按原文件的内容标识缓存，替换图标后不会复用旧版本。更新界面时保留仍在目录内的预览缓存；新版本优先预缓存壁纸和头像，明确排除人物图库的头像，下载原图仍需联网。人物图库可通过页脚默认折叠的「更多」或原有直达网址进入，可在自己的浏览器内选择保留导航入口；这不改变公开目录和资源的访问边界，详见其目录内的访问说明。

安装时可选预览的网络预取最多等待 8 秒，超时会取消未完成的预取，让已完整校验的界面完成安装；必需界面文件仍须全部校验成功。游戏封面的模糊背景随对应懒加载图片成功加载后显示，避免背景提前请求远处的封面。

展示标题和处理说明可在 `catalog.json` 中编辑，`title` 和 `note` 必须为字符串，图片路径不能重复。游戏封面的标题取自作品清单，不保留处理说明；替换时重新核对并更新来源，自动内容标识会随新文件更新。手动修改后再次运行更新命令，让缓存版本同步。其他资源替换原图后保留标题，旧的处理说明会清除，请按新图补充。GIF 的列表预览显示首帧，下载保留动画；SVG 使用原矢量图预览。

金融图标的 `title` 按品牌总部所在地的常用名称填写，中国大陆银行使用中文，国际品牌保留总部常用名称，例如 DBS、OCBC、UOB。仅维护一个展示标题，不追加中英文对照、地区适用说明或搜索别名；搜索直接匹配现有标题和文件路径，不另建总部或语言字段。

适用设备会按实际尺寸和比例初步分类为手机、电脑、平板；无法明确区分的尺寸（例如 1080×1920）保留为「待分类」。可在 `catalog.json` 中用 `device` 修正：`phone`、`desktop`、`tablet`、`unknown`，手动分类优先。只有手机竖屏壁纸提供锁屏效果，其他图片使用普通预览。

设备表示经确认的使用场景，不等同于画面方向；例如现有 7500×5000 的 3:2 壁纸仍属于电脑壁纸。继续使用 `wallpapers/<内容分类>/<尺寸>/` 归档，不为设备再复制或移动原图。网页的设备入口独立于折叠筛选，方向和尺寸选项随上级条件更新；只有实际存在多个取值时才显示对应筛选，已选条件仍可清除。新增资源时无需手工维护菜单，仍须核对内容分类与 `device`。

上传前运行 `python3 scripts/update_catalog.py --check`，确认检查通过，并将原图与生成文件一起提交。此命令只检查、不写文件；它检查路径、尺寸、图标标准及生成文件是否同步，内容分类与适用设备仍需人工判断。

游戏封面还须人工核对语言选择：先确认候选是同一作品的正式发行封面（包括正式数字商店封面），排除自制英文版、修改 Logo、非正式翻译及 AI 重绘；再比较原图细节、模糊与压缩痕迹，并在相同展示大小下检查构图和裁切。条件相近时选英文，没有合适英文版或英文版明显更差时保留日文或其他正式版本。作品只有英文合集发行时，不能拿合集封面替代单作。`--check` 不判断图中语言或自动排名，不新增语言字段或按 `cover.region` 强制语言；现有游戏封面测试仍校验可选资料、源图保留、一作一图、额外收藏及替换后的内容标识与预览更新。
