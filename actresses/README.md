# 女优人物图库

人物资料图库，不收录影片封面、作品信息或视频。初始收录 174 位人物、每人一张主头像；2023–2025 年完整年度 TOP 100 共引用 170 位人物，另补四位历史人物。名人堂为本项目精选的 10 人，可和年度榜重叠；「全部女优」指本库全部已收录人物，不表示行业完整名录。

## 数据与页面

- `data.json` 是唯一的人物登记表。`p0001` 等本地 ID 不含名字、年份或栏目，登记后不重排、不复用。改名修改 `name`，旧名留在带来源的 `aliases`；`identities.fanza` 可登记多个已人工确认属于同一人的官方 ID。图片放在 `portraits/<人物ID>.<源格式>`，每人一个文件。
- `rankings/<年>.json` 保存原始顺序、表记、官方 ID、出处和原头像链接，以及获取日、五个源页面的 SHA-256。保留排名事实提取，不保存广告、作品介绍或视频。工具按官方 ID 映射人物，未知 ID 或未经审核的新表记会阻止生成，不按相似名字合并。
- 名人堂是人物的 `hallOfFame` 属性，带说明、依据和审核日，不维护第二份人物或图片。首批从 2009、2011、2014、2016 年官方租赁榜中精选早期代表人物；只将这些来源作为收录依据，不导入完整早期年度榜，也不宣称是官方名人堂。
- `catalog.json` 是生成的展示数据；人物数据和栏目逻辑独立于图片扫描，网页只读取已发布目录，不抓取上游。新增栏目引用人物 ID，无需移动头像。

入口为 `#actresses=annual&year=2025`、`#actresses=hall`、`#actresses=all`。人物链接为 `#actresses=all&person=p0054`；同一 ID 始终打开同一资料。年份、搜索、字母索引和分页支持分享、刷新、前进与后退。列表最多 48 人，只显示头像、姓名、已记录罗马字及年度名次；详情集中显示别名、已收录年度的最佳名次与上榜次数、名人堂状态和来源。

统计只从 2023 年起实际收录的同口径榜单计算，不能解释为生涯记录。未经确认的生日、出道日、退休状态和中文译名不补全。初始仅 20 人有可追溯罗马字表记，字母索引提供「未录罗马字」入口；其余可用日文名和已确认别名搜索，不自动音译或猜测姓名。

## 年度来源

采用 [FANZA 月额 DVD 租赁官方年度榜](https://www.dmm.co.jp/rental/-/ranking/=/article=actress/t=year_2025/)，起点为 2023 年。2023、2024、2025 年各五页、连续 1–100 名，具有相同页面体系和稳定人物 ID，可直接保留年度顺序，无需月度加权。

该榜只反映平台月额 DVD 租赁口径，不能和 DVD 销售、视频配信、单品租赁、杂志半年榜或第三方积分榜混称为统一人气榜；官方未公开本数、销售额及完整计算细则。本次排除了月度覆盖不齐的第三方 2025 积分榜，以及无法持续核对的杂志／销售排行。2026 年尚未结束，不生成年度榜；不为补全历史追溯全部早期榜单。新增不同口径时应建立独立系列、显示明确标签、分别统计，不能混入当前系列。

## 头像与来源

主要来自 [Gfriends](https://github.com/gfriends/gfriends) 的固定提交 `de8298f27afb4469100e39c159443c139ef0ef42`（2026-10-05）；少量缺失者采用 FANZA 官方人物头像。每张记录上游路径、提供者、固定提交／原文件 URL、获取日、审核日和与保存文件一致的 SHA-256。Gfriends 分组是上游出处线索，不冒充已核实的原摄影者或再分发授权。文件树只用于已核对的罗马字表记，不自动决定身份，不批量收录未核实的素人名义。

初次对多张候选人工检查，综合清晰度、自然程度、主体、构图和来源选择，排除明显水印、明显裸露、多人构图和不适合资料展示的候选。未选用 `AI-Fix-` 图，不使用 AI 放大、换脸、重绘或去水印。上游部分 `.jpg` 实际是 PNG，按真实格式保存，保留原始字节与尺寸，不重新压缩原图。

网页以 3:4 容器和 `object-fit: contain` 保留主体，不拉伸或强行裁去更好的构图。列表沿用等比 WebP，宽度最多 420 像素，懒加载；打开详情后才请求源图。初始源图约 27.9 MB，预览约 3.6 MB，完整目录约 330 KB，首屏按可见范围加载预览。离线沿用最多 32 张预览的缓存上限，不自动预缓存整个女优图库。

## 更新与审核

所有入库都经人工审核；自动流程只抓取候选、生成目录并验证约束。安装现有 `scripts/requirements.txt` 后，在仓库根目录运行（审核目录必须在仓库外）：

```sh
# 下一完整年度：先获取五页排名事实，不修改人物库
python3 scripts/actress_sources.py annual --year 2026 --output ../actress-review
# 比较已选头像的上游版本，写出变更／不可用报告
python3 scripts/actress_sources.py portraits --output ../actress-review
# 离线检查共享姓名与相似图片，仅给人工审核提示
python3 scripts/actress_sources.py duplicates --output ../actress-review
```

2026 年内上述年度命令会拒绝运行，只在年度结束后使用。未结束年份、缺页、地区限制、提示页、解析结构改变或重复官方 ID 都会中止获取，不回退到另一口径或生成不完整榜。GitHub Actions 的 **Review actress sources** 可手动运行审核并下载报告，只有读取权限，不自动提交、换图、增加人物或合并身份；既有 **Check gallery** 在提交时校验全部登记和生成文件。

新增人物先核对官方 ID、主名、别名及各来源是否同一人，再分配未用过的 ID，挑一张主头像，记录来源与审核日。新年度仅引用已有身份；新人物审核后再将来源快照复制到 `rankings/`。头像更新先比较完整候选和当前图，通过后替换文件并更新来源摘要，不因来源、年份或栏目变化另存副本。

人物合并须人工确认：保留一个 ID，把原官方 ID 和有依据的别名合到保留记录，删除重复头像，在 `redirects` 登记旧 ID 到保留 ID 的直接映射，旧链接继续有效。禁止循环、链式转跳和复用旧 ID。同年度两个上游 ID 若映射到同一人会停止生成，应核查原榜并明确解决，不擅自相加或选较高名次。同名、共享别名和近似图都不是身份确认。

完成审核后运行并提交生成文件：

```sh
python3 scripts/update_catalog.py
python3 -m unittest discover -s scripts -p 'test_*.py'
node --test scripts/test_*.cjs
python3 scripts/update_catalog.py --check
```

校验拒绝重复人物 ID／来源 ID／主名、相同图片摘要、孤立图片、摘要不匹配、未经审核改名、不完整年度和意外改变人物 ID。相似图片用 64 位差值哈希、距离 ≤5 提示复核；这是图像去重提示，不是人脸识别或人物合并证据。

## 长期增长与版权

只保留每人一张源图和一张当前预览，不镜像 Gfriends，不保存候选、完整文件树或每次上游更新。新榜单一般只增加很小的文本与确实新增人物的头像；生成器清理失效预览。替换图片仍会增长 Git 历史，删除旧文件无法缩小历史，因此不定期追随上游换图。

当前规模沿用 Pages 普通文件，避免额外服务和 Git LFS；Pages 不会自动把 LFS 指针当图片发布。若规模或历史影响克隆／发布，应先测量再迁移原图到对象存储／发布资产，保留稳定 ID、来源记录和小预览，调整生成器的资源读取及地址解析而不用重组栏目。本次未重写历史，也不提前引入存储服务。

头像版权归摄影者、演员所属经纪公司、原网站及其他相应权利人，本项目不授予第三方图片许可，不将 Gfriends 声明当作图片开源许可。保留 [Gfriends 条款与免责声明](https://github.com/gfriends/gfriends/blob/de8298f27afb4469100e39c159443c139ef0ef42/README.md#法律信息及免责声明)，其项目限定技术／学术交流，禁止商业和盈利用途。权利人要求移除时，应删除头像及相应人物／栏目引用，生成目录和缓存版本；需要移除 Git 历史时另行处理，普通删除不等于历史清除。
